# 메뉴 개편 결정 기록

출발점: 2026-10 홈페이지 제작 회의 문서의 "멀티미디어 > 홈페이지 메뉴" 표. 바이블 스터디는 이번 범위에서 제외.

## 메뉴 구조
- 교회 안내: 교회 소개 `/about`, 섬기는 분들 `/pastor`, 예배 안내 `/service`, 오시는 길 `/location`
- 생명의 말씀: 설교말씀 `/media`, 매일의 묵상 `/meditation`, 목회편지 `/letters`
- 교회소식: 주보 `/news/bulletin`, 갤러리 `/news/gallery`, 공지사항 `/news/notice`

## 결정과 이유
- **목회편지는 생명의 말씀 아래.** 회의 문서에 없는 메뉴라 사용자에게 확인. 담임목사의 말씀 성격이라 이쪽에 묶음.
- **예배실황·주일설교·수요설교는 별도 메뉴가 아니라 설교말씀 페이지의 탭.** 사용자 요청.
- **탭은 재생목록이 아니라 영상 제목으로 분류.** 2026-10-03 확인 시 수요예배 재생목록은 4월, 주일예배(실황) 재생목록은 8월 이후 갱신되지 않음. 주일설교 재생목록만 최신. 제목은 규칙이 일정함(`... l 드림숲교회 주일설교`, `9월 30일 수요`, `9월 27일 주일예배`). 대신 채널 RSS는 최근 15개만 주므로 탭마다 한 달치 정도만 보임 → "YouTube에서 더 보기" 링크로 보완.
- **매일의 묵상은 목회편지와 같은 `posts` 테이블에 `category = 'meditation'`으로 저장.** 기존 게시판 코드를 재사용하기 위함.
- **기존 주소는 유지.** 외부에 공유된 링크가 깨지지 않도록 `/media`, `/letters`, `/service`, `/pastor` 그대로 둠.
- **주보·갤러리·공지사항은 이번엔 준비 중 화면.** 파일 업로드 저장소 연결이 필요해 범위를 나눔.

- **게시판 설정은 `src/lib/boards.ts`, DB 코드는 `src/lib/posts.ts`로 분리.** 관리자 글쓰기 폼(클라이언트 컴포넌트)이 게시판 이름 목록을 써야 해서, DB 드라이버를 끌어오지 않도록 나눔.
- **관리자 액션 이름을 `createLetterAction` → `createPostAction` 등으로 변경.** 이제 목회편지 전용이 아니므로. 수정할 때는 게시판을 바꾸지 않고(숨은 필드로 기존 분류 전달), 새 글에서만 고름.
- **관리자 화면 제목을 "목회편지" → "글 관리"로 변경.** 두 게시판을 함께 관리하므로.

## 2단계: 묵상 녹음 업로드
- **녹음 파일은 Cloudflare R2, DB에는 파일 위치(`audio_key`)만.** 녹음 한 편이 7~15MB라 DB에 넣지 않음. Vercel Blob(무료 1GB)은 매일 올리면 몇 달 만에 차서 R2(무료 10GB, 전송 무료)로. Oracle VM은 저장 전용이면 무료 서버 회수 조건(7일간 CPU·네트워크·메모리 20% 미만)에 걸리고 관리 부담이 커서 제외.
- **R2는 사용자 개인 Cloudflare 계정**(yeomjongsung@gmail.com). 맥의 기본 wrangler 로그인은 회사 계정이라 `HOME=~/.cloudflare-personal`로 분리 실행.
- **브라우저 → R2 직접 업로드(서명 주소).** Vercel 서버 함수는 요청 본문이 4.5MB로 제한됨.
- **버킷은 비공개, 재생은 볼 때마다 6시간짜리 서명 주소.** dfch.kr이 없어 공개 도메인을 붙일 수 없고, r2.dev 공개 주소는 운영용이 아님.
- **서명은 `aws4fetch`.** AWS SDK보다 훨씬 가볍고 R2 문서에서 안내하는 방식.
- **파일 형식은 확장자로 판단하고 Content-Type을 서버가 정함.** 휴대폰마다 `file.type`이 비거나 달라서. 업로드 키는 `meditation/날짜-UUID.확장자`이고, 저장할 때 이 형식만 받음.
- **글쓰기 폼은 게시판 선택칸 대신 `/admin/new?board=`로 나눔.** 게시판마다 입력칸이 달라짐(묵상: 본문·녹음·메모 선택).
- **녹음 교체·글 삭제 시 이전 R2 파일을 지우되, 실패해도 저장·삭제는 진행.** 업로드만 하고 저장하지 않은 파일은 남음(용량이 작아 당장은 두고 필요하면 정리 기능 추가).
- **Vercel의 `DATABASE_URL`·`ADMIN_PASSWORD`·`SESSION_SECRET`은 민감 정보로 설정돼 있어 `vercel env pull`로는 `[SENSITIVE]`만 내려옴.** 로컬 확인용 DB 주소는 Neon에서 직접 받아야 함. 운영 DB에 테스트 글이 쌓이지 않도록 Neon 개발 브랜치 사용을 권장.

- **로컬 개발 DB는 Neon `dev` 브랜치**(2026-10-03 `production`에서 복제, 자동 삭제 Never). 운영 브랜치 `production`은 8월 8일부터 사용이 없어 보관(archived) 상태였음. `posts.category`에는 CHECK 제약이 없고 `content`는 NOT NULL이라, 메모를 비우면 빈 문자열로 저장.
- **WAV는 브라우저에서 MP3(모노 64kbps)로 바꿔 올림.** 15분 WAV는 약 150MB라 R2·업로드에 부담이 큼. 서버 변환은 Vercel 요청 크기 제한(4.5MB)과 ffmpeg 부재로 어려워 브라우저에서 처리. 인코더는 `wasm-media-encoders`(LAME의 WASM판, MIT, gzip 약 66KB, 녹음을 고를 때만 불러옴). 휴대폰 메모리를 위해 `decodeAudioData`로 통째로 풀지 않고 WAV를 직접 읽어 약 1초씩 처리. m4a·mp3 같은 압축 파일은 다시 변환하면 음질만 떨어지므로 그대로 올림. 변환할 수 없는 WAV(드문 형식)는 원본을 올림(100MB 제한 적용). 확인 결과: 3분 44.1kHz 스테레오 WAV 30.3MB → MP3 1.4MB, 약 2초, `afinfo`로 길이 180.0초 확인.
- **배포 순서**: 운영 DB에 `001_posts_audio_key.sql` 적용 → Vercel에 `R2_*` 4개 등록 → 배포. 칸 추가는 기존 코드와 호환되므로 DB를 먼저 바꿔도 지금 운영 사이트는 깨지지 않음.
