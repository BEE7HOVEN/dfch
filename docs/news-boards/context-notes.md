# 교회소식(공지사항·갤러리·주보) 결정 기록

## 범위 (2026-10-04 사용자 확인)
- 게시판은 **공지사항만**(관리자 작성). 교인이 쓰는 게시판은 회원 로그인·스팸 관리가 필요해 제외.
- 갤러리는 **앨범형**(행사별 여러 장).
- 주보는 **사진(여러 장)과 PDF 둘 다** 받는다.

## 설계
- **글 정보는 기존 `posts` 표, 파일은 새 `attachments` 표 + R2.** `posts`는 바꾸지 않고 분류값만 `notice`·`gallery`·`bulletin` 추가(CHECK 제약 없음 확인됨). 첨부는 글 삭제 시 DB에서 함께 지워지게(ON DELETE CASCADE) 하고, R2 파일은 코드에서 지운다.
- **사진은 브라우저에서 줄여서 올린다.** 휴대폰 사진 3~8MB → 긴 변 2000px JPEG(약 0.4MB) + 미리보기 600px(약 0.06MB). `createImageBitmap`의 회전 정보 반영으로 눕는 사진을 바로잡는다. Vercel 이미지 최적화는 무료 한도(월 5천 회)가 있어 쓰지 않는다.
- **보기 주소는 서명 주소지만 몇 시간 동안 같은 값**이 나오게 서명 시각을 시간 단위로 맞춘다. 매번 주소가 바뀌면 브라우저가 사진을 다시 받기 때문.
- 업로드는 묵상 녹음과 같은 방식(브라우저 → R2 직접, 서버는 서명 주소만 발급). 업로드 함수는 `src/app/admin/upload.ts`로 공용화.
- **주보 제목은 선택.** 비우면 서버가 날짜로 "YYYY년 M월 D일 주보"를 만든다(`titleRequired: false`).
- **공유는 Web Share API + 링크 복사.** 휴대폰은 기본 공유 창에서 카카오톡을 고르고, PC는 링크를 복사한다. 카카오 SDK(카톡 전용 버튼)는 카카오 개발자 앱 키와 도메인 등록이 필요해 이번엔 넣지 않음. 링크 카드는 Open Graph로 만든다(`src/lib/postMetadata.ts`, 기본 주소 `src/lib/site.ts`의 `SITE_URL`, dfch.kr 연결 후 환경변수로 변경).
- **배포 순서 주의**: 새 코드는 글 삭제 때 모든 게시판에서 `attachments`를 조회하므로 운영 DB에 표를 먼저 만들어야 한다.
- 테스트 중 dev 서버가 자동 생성하는 `.next/dev/types/validator.ts`가 깨져 타입체크가 실패한 적이 있음(빌드와 dev가 동시에 쓴 것으로 추정). 파일을 지우고 dev 서버를 재시작하면 해결.

## 메인 화면 최근 공지·묵상 (2026-10-04)
- 메인(`/`)은 방문이 가장 많아 매번 DB를 읽지 않도록 **5분 재검증(ISR)** 으로 두고, 관리자 저장·수정·삭제 때 `revalidatePath("/")`로 즉시 갱신한다. Vercel CPU 무료 한도 초과를 겪은 뒤라 요청마다 함수가 도는 구조를 피함.
- 확인: 빌드한 앱에서 메인 응답이 `x-nextjs-cache: HIT`, DB에 직접 넣은 글은 바로 안 보이고, 관리자 화면 저장 직후에는 바로 보임.
- DB를 못 읽으면 칸만 비우고 메인 전체는 정상 표시(`HomeRecentPosts`의 `safeRecent`).
- **메인 갤러리 표지는 고정 주소 `/r2/<key>`** 로 넣는다. 메인 HTML이 캐시돼 6시간 넘게 쓰이면 서명 주소가 만료돼 사진이 깨지기 때문. 이 라우트는 갤러리 미리보기(`gallery/…_t.jpg`)만 허용하고, 새 서명 주소로 302 넘겨주며 결과를 CDN에 1시간 캐시한다.
- **메인 최근 주일설교는 브라우저에서 `/api/youtube`를 부른다.** Vercel 서버(Node)에서 유튜브 RSS가 막혀 이 API만 Edge로 돌리고 있어서(커밋 "Edge Runtime으로 전환하여 YouTube RSS 차단 우회"), 메인 서버 렌더링에서 직접 부르지 않는다. API는 1시간 캐시.
