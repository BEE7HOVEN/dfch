# 초청음악회 예매 시스템 계획

요청(2026-10-27): 홈페이지 안에서 음악회를 예매받는다. 좌석 지정은 없고, 남은 좌석을 항상 보여 준다.

## 정해진 조건

- 전체 200석, 이 중 **50석은 현장 접수 몫**으로 처음부터 찼다고 본다. 온라인으로는 **150석**까지 받는다.
- 좌석은 **예매 인원 기준**으로 센다(4명 예매 = 4석).
- 입력: 예매자 이름, 전화번호, 인원(1~4명), 개인정보 동의(필수).
- 예매 기간: **지금 즉시 ~ 2026-12-05 정오 12시(한국 시간)**. 관리자가 수동으로도 열고 닫을 수 있다.
- 문자 발송은 하지 않는다. 완료 화면의 예매번호를 캡처해 두도록 안내하고, 입장은 이름으로 확인한다.
- 같은 전화번호로는 한 번만 예매한다.
- 공연은 **2026-12-05(토) 오후 4시**. 예매는 같은 날 정오에 마감한다. 예매자 정보는 공연 종료 후 7일 이내(12월 12일까지) 파기한다.

## 설계

- **상수**: `src/lib/concert.ts` — `CAPACITY=200`, `ONSITE_RESERVED=50`, `ONLINE_LIMIT=150`, `MAX_PARTY=4`, `CLOSES_AT="2026-12-05T12:00:00+09:00"`.
- **DB** (`db/migrations/004_concert.sql`, 적용 전에 사용자 확인):
  - `concert_reservations(id, number serial, name, phone, party_size 1~4 CHECK, status 'active'|'cancelled', consented_at, created_at)`. 전화번호는 숫자만 저장하고, `status='active'`인 행에만 전화번호 유일 인덱스를 둔다(취소 후 다시 예매 가능).
  - `concert_config(id=1, open boolean)` — 관리자 열기·닫기 스위치.
- **초과 예매 방지**: Neon `sql.transaction([잠금, 조건부 INSERT])`. 같은 트랜잭션에서 `pg_advisory_xact_lock`을 잡고, 남은 좌석이 인원 이상일 때만 INSERT한다(0행이면 "남은 좌석이 N석뿐입니다").
- **공개 화면** `/concert` (`force-dynamic`): 남은 좌석(200석 기준, 현장 몫 포함 표시)과 진행 막대, 20석 이하 안내, 예매 폼, 완료 카드(예매번호·"캡처해 두세요"), 마감·기간 외 화면. 서버 액션으로 제출한다.
- **스팸 방지**: 숨은 입력칸(honeypot), 서버 쪽 이름·전화번호 형식 검사. 그 이상은 하지 않는다.
- **개인정보 동의 문구**(조사 반영):
  - 수집 항목: 이름, 전화번호
  - 이용 목적: 공연 예매 확인, 입장 확인, 공연 변경·취소 시 연락
  - 보유 기간: 공연 종료 후 7일까지 보관 후 파기
  - 거부 권리: 동의를 거부할 수 있으며, 거부하면 온라인 예매를 할 수 없다(현장 접수 가능)
  - 체크박스는 비어 있게 시작하고, 동의 없이는 제출되지 않는다. 동의 시각을 저장한다.
  - 만 14세 이상만 예매할 수 있다고 안내한다.
- **별도 처리방침 페이지는 만들지 않는다**(사용자 결정 2026-10-27: 이 사이트는 예매 외에 개인정보를 받지 않는다). 대신 동의 문구를 펼치면 항목·목적·보유 기간(12월 12일까지)·파기 방법(전자 파일 삭제)·문의처(031-421-6191)·서버 저장 안내가 모두 보이게 한다. 법상 처리방침 공개 의무(제30조)의 면제 여부는 확인하지 못했다.
- **관리자** `/admin/concert`: 예매자 목록(예매번호·이름·전화·인원·시각), 남은 좌석, 취소(좌석 복구), 열기·닫기 스위치, CSV 내려받기, "예매자 정보 모두 삭제"(공연 후 파기용). 관리자 첫 화면에서 연결한다.
- **연결**: 메인 배너는 기존 배너 글의 `link_url`에 `/concert`를 넣어 쓴다(코드 변경 없음). 사이트맵에 `/concert`를 넣는다.

## 결과 (2026-10-27, 개발 DB·로컬)

- 동시 예매: 남은 3석에 2명짜리 5건을 동시에 보내 성공 1건, 합계 149석(150 이하). 같은 전화번호 중복과 좌석 초과도 거절.
- 화면: 동의 없이 제출 불가, 예매 완료(예매번호), 남은 좌석 150→148, 중복 안내, 닫기 시 마감 화면, 취소 시 좌석 복구, CSV(한국 시간), 확인 문구 후 전체 삭제, 휴대폰 폭 가로 넘침 없음.
- 개발 DB의 시험 기록은 모두 지웠다.
- 운영 DB 표는 `ensureSchema()`가 처음 쓸 때 자동으로 만든다(Vercel 명령줄이 다른 팀 계정이라 운영 DB 주소를 받지 못해서). 배포 뒤 `curl -s https://dfch.org/concert | grep -q "남은 좌석"`로 확인했고, 운영에서 실제 예매는 시험하지 않았다.
- 메인 배너로 연결하려면 관리자에서 배너 글의 링크를 `/concert`로 둔다.
